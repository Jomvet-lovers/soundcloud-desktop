# anti-slop 監査 002 (2026-10-10) — ユーザー指摘と互換チェック

- 対応コミット: `7b4b0c39` (feat(ui): Tauri-native sliders + right-click menus)。
- ユーザー指摘:
  1. 再生バー・音量バー・イコライザーにピル型が使われている。
  2. 右クリック機能がない。

## 1. スライダー(ピル型の排除)

egui 標準 `Slider`(太いピル型レール)を全廃し、Tauri の実装に合わせた
自作スライダー 3 種に置換 (`egui::Slider` の使用箇所は 0 になった)。

- **`widgets::range_slider`** — Tauri の `input[type=range]` (accent-color) 相当。
  実機計測 (cmp-tauri-home.png のピクセルサンプリング) に一致:
  4px トラック (角丸 2) + 1px 白 50% 枠 + 白 20% コア、左側はアクセント充填、
  15px のアクセント円サム。無効時は 40%。
  - 適用: 再生バーのシーク / 音量 (w-24 = 96px) / サウンドチューニングの Speed・Pitch。
- **`widgets::eq_band_slider`** — Tauri `BandSlider` 相当。140px・3px レール
  (白 10%) + 中心線 + 上下充填 (正 = emerald #34d399 55% / 負 = blue #60a5fa 55%)
  + 16px 円サム。0.5dB 刻み。
- **`widgets::plain_range_slider`** — Tauri 設定の `RangeSlider` 相当。
  4px 白 10% トラック + 16px 白サム (枠・充填なし)、step 対応。
  - 適用: Settings の壁紙 (Darkening / Edge darkening / Blur) と Audio cache limit。

## 2. 右クリック機能

Tauri の `onContextMenu` 全箇所を洗い出し、欠けていた面を実装。

- **再生バー左セクション**: アートワーク / タイトル → トラックメニュー、
  アーティスト名 → ユーザーメニュー (Tauri NowPlayingBar と同じ)。
- **サイドバー Quick Access の pin** → プレイリストメニュー
  (Go to playlist / Copy link / Remove from Quick Access)。
- **アーティスト名の右クリック → ユーザーメニュー** (Go to profile / Copy link):
  `track_card` / `track_card_stats` / `track_row` (ライブラリ・ユーザー・
  プレイリスト・アルバム等の行) / トラックページのヒーロー。
  ウィジェットから shell へは小さな要求キュー (`widgets::MenuRequest`) で渡す
  (ビューの Action 列挙を増やさない)。
- **メニューの外観を Tauri `TrackContextMenu` に一致**: 236px / 角丸 12 /
  #141417 / 白 10% 枠 / 内側 6px / 項目 40px・角丸 8・13px medium・
  アイコン 15px 白 50% / 区切り線 白 6%。
- **トラックメニューの項目**: 先頭 4 項目 (Add to library / Add to Next up /
  Add to playlist / Share) は Tauri と同一の順・ラベル・アイコン。
  Tauri に無い既存項目 (Not interested / Download... / Go to track /
  Go to artist) は区切りの下に残置 → **削除してよいか要確認**。

- **キューパネル**: Tauri は 360px ドロワー + 背景 black 60% + ヘッダー

## 8. 追記 (2026-10-10): WebView2 常駐コストの削減 (perf)

ユーザー指摘「タスクに webview2 が出ている。egui+wgpu はパフォーマンスの
ためなのに」への対応 (コミット `f7e3ed50`)。

- **構成の確認**: WebView2 は `--wry-host` 子プロセスが使う 2 webview
  (ログイン窓 + 隠し writer)。UI 描画は 100% egui+wgpu で、本体プロセスは
  27MB。WebView2 は認証と書き込み同期 (DataDome 回避) のためだけに存在する。
- **実測** (msedgewebview2 を親チェーンで本アプリに帰属):
  旧: 12 プロセス / 約 1,558MB。内訳の主因は
  1. ログイン webview が起動時に必ず生成され signin の SPA を常駐
  2. writer が home の SPA を読み込み、レンダラ 1 つが 805MB
- **対策**:
  1. **ログイン webview を遅延生成** (`ensure_login` / `ChildState`)。
     サインイン操作をしたときだけ生成する。`IsVisible` は生成せず false、
     `Hide` は no-op。サインイン完了後は既存の `login_close` が
     `about:blank` 化して SPA を解放する (cookie は共有 WebContext に残る)。
  2. **writer のホームを `https://soundcloud.com/404` に変更**。同一オリジン
     (cookie / fetch / DataDome 条件は不変) だがフィードを読まない軽量 SPA で、
     メイン renderer が 805MB → 317MB に。
- **結果**: 通常起動時の WebView2 は **9 プロセス / 約 754MB**
  (旧 12 / 1,558MB) = **約 800MB / 3 プロセス削減**。サインイン時のみ
  ログイン webview が一時的に加算され、完了で解放される。
- **検証**: `--smoke-writer` → `status=200 captcha=false` ✓。
  `--smoke-login` → `login window created (lazy)` + フロー完走 ✓。
  `cargo test` 45 件 ✓。
- **メモ**: `--disable-gpu` は実測でほぼ差が無く (renderer がソフトウェア
  合成でやや増える)、ログイン窓の描画も考慮して不採用とした。
